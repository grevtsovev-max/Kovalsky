# Kovalsky Newsroom

Сервис мониторит новости о цифровых активах, ведёт редакционную память и готовит русскоязычные публикации для Telegram.

## Работа сервиса

Приложение включает сбор и редакторскую обработку новостей, бота обратной связи и веб-панель. Активные источники, расписание и доступ к кабинету определяются настройками среды выполнения.

## Изменение и доставка кода

Исходный код хранится в Git. Параметры среды выполнения, секреты и рабочие данные обслуживаются отдельно от исходников.

## Настройки и данные

Обработка использует три роли и постоянную очередь: по умолчанию два исполнителя параллельно читают и разбирают независимые материалы, координатор применяет результаты и выполняет штатный допуск. Общий бюджет AI сохраняется в базе и учитывает каждый HTTP-повтор. Настройки параллельности, окна запросов и резервов приведены в `config.example.toml`; денежная оценка требует тарифов используемых моделей. Схемы и процессы — в `AGENT_ARCHITECTURE.md`, показатели очереди и расхода — в `newsroom health` и кабинете.

- `config.example.toml` — безопасный шаблон конфигурации.
- `config.toml`, секреты и базы данных не хранятся в Git.
- Не фиксируй в Git пути к локальным или рабочим данным.
- Не публикуй значения API-ключей, токенов, личные конфиги, базы данных или журналы.

## Основные документы

- `AGENTS.md` — инструкции для работы с проектом.
- `AGENT_ARCHITECTURE.md` — сущности, роли, целевой процесс, обратная связь и схема реализации.
- `AGENT_LOGIC.md` — архитектурные инварианты.
- `EDITORIAL_RULES.md` — правила отбора, проверки и оформления новостей.
- `MONITORING_MAP.md` — темник и ориентиры по источникам; активные подключения задаются конфигурацией.
- `INTEGRATIONS.md` — состояние внешних интеграций.
- `KANBAN.json` — задачи, показываемые в панели.

## Разработка

Требуется Python 3.9 или новее. Основной код находится в `newsroom/`, тесты — в `tests/`. Секретные и рабочие файлы должны оставаться вне репозитория.

Для запуска установите зависимости из `pyproject.toml` в отдельное Python-окружение. Дайджест использует русский морфологический словарь `pymorphy3`.

`newsroom digest-run` запускается отдельной постоянной службой с той же конфигурацией и базой, что и сборщик. Служба отправляет ежедневный выпуск в 20:05 по Москве, недельный — по субботам в 19:00; длительный цикл сбора её не задерживает. `newsroom digest --kind daily` позволяет запустить ту же проверку срока и доставку вручную. `--rebuild-unsent` пересобирает только заведомо неотправленный черновик с сохранением истории; успешные и неизвестные отправки изменять запрещено.

Перед выпуском каждый пост проверяется по фактическому содержимому публичного канала: удалённые посты исключаются, заголовки берутся из текущего текста. Неопределённое наличие блокирует отправку после трёх попыток чтения. `newsroom digest-repair --kind daily --date ГГГГ-ММ-ДД` проверяет уже опубликованный выпуск и исправляет его редактированием прежнего сообщения через штатную проверку и сохраняемую доставку.
