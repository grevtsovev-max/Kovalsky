# Kovalsky Newsroom

Сервис мониторит новости о цифровых активах, ведёт редакционную память и готовит русскоязычные публикации для Telegram.

## Работа сервиса

Рабочий экземпляр запущен на Linux-сервере как три службы systemd:

- `kovalsky-newsroom` — сбор, проверка и публикация новостей;
- `kovalsky-review` — редакторский бот и обработка обратной связи;
- `kovalsky-dashboard` — веб-панель, доступная локально на сервере.

Панель по умолчанию слушает `127.0.0.1:8765`. Для доступа извне нужен отдельный защищённый прокси или SSH-туннель.

## Изменение и доставка кода

Работа над исходниками ведётся в проекте Codex. Готовые изменения отправляются в ветку `main` репозитория GitHub. GitHub Actions автоматически доставляет на сервер изменения в `newsroom/` и `KANBAN.json`, затем перезапускает службы. Изменения документации и тестов не вызывают выкладку.

Журнал запусков и результат выкладки доступны во вкладке **Actions** репозитория. При неудачном запуске служб скрипт выкладки возвращает предыдущую рабочую версию, когда она есть.

## Настройки и данные

- `config.example.toml` — безопасный шаблон конфигурации.
- `config.toml`, секреты и базы данных не хранятся в Git.
- На сервере настройки находятся в `/etc/kovalsky/`, рабочие базы и ключи — в `/var/lib/kovalsky/data/`.
- Не публикуй значения API-ключей, токенов, личные конфиги, базы данных или журналы.

## Основные документы

- `AGENTS.md` — инструкции для работы с проектом.
- `AGENT_LOGIC.md` — архитектурные инварианты.
- `EDITORIAL_RULES.md` — правила отбора и оформления новостей.
- `MONITORING_MAP.md` — темы, сущности и источники для мониторинга.
- `INTEGRATIONS.md` — состояние внешних интеграций.
- `KANBAN.json` — задачи, показываемые в панели.

## Разработка

Требуется Python 3.9 или новее. Основной код находится в `newsroom/`, тесты — в `tests/`. Секретные и рабочие файлы должны оставаться вне репозитория.
