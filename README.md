# Kovalsky Newsroom

Сервис собирает материалы, применяет первый тематический фильтр и автоматически готовит, проверяет и публикует посты новой редакции. Рабочие правила и дословные референсы описаны в `EDITORIAL_RULES.md` и входят в каждый запрос редактору.

Включение редакции: `[editorial] enabled = true`. Настройка не снимает остановку агента владельцем. В `newsroom run` сбор и редакция работают параллельно. В кабинете доступны версии, исходники, результаты проверок и повтор незавершённой подготовки.

Поиск редактора ограничен локальным архивом. Одна доработка; подтверждённые повторы опубликованных фактов сохраняются без повторной доставки. Новые существенные факты допускают отдельный выпуск. Доставка одного готового поста защищена от повторной отправки при сбое.

Цель — 5–10 минут от получения до публикации, без жёсткого редакторского таймера. Старые материалы архивируются без автоматического массового выпуска.

Команды: `run`, `once`, `health`, `pending`, `filter-audit-export`, `dashboard`, `agent`, `admin-publish`. Последняя сохраняет отдельную отправку точного текста по явной команде владельца.

Код — в `newsroom/`, тесты — в `tests/`. Секреты, рабочие настройки, журналы и базы не входят в Git. Изменения `newsroom/` в main автоматически выкладываются на сервер.


### Ретроспективный аудит

В кабинете откройте «Аудит», выберите сутки, неделю или 30 дней и нажмите «Подготовить отчёт». После завершения нажмите «Обновить». Проверка делает отдельные запросы к ИИ и учитывается в расходах. Посты и решения редакции не изменяются.

Команда: `newsroom --config config.toml retrospective --hours 24`. Вариант `--journal-only` собирает путь материалов без запросов к модели и работает при остановленном агенте. Результат — JSON; отчёт также сохраняется в рабочей базе и доступен в кабинете.

Отчёт включает все материалы, впервые полученные за период, их сохранённые версии, фильтр, редакционные события, проверки и доставку. Состояния фиксируются перед оценкой. Оценка проводится по текущим правилам и сохранённому темнику; это не утверждение, что правила были такими же в момент старого решения. Ошибочный отказ и лишняя публикация сопровождаются точными проверяемыми цитатами. Незавершённые и неизвестные отправки отделены от отказов. Без доказательств результат — «Недостаточно доказательств». При недоступности модели сохраняется частичный отчёт. Медиана и задержки считаются по материалам с подтверждённой публикацией, включая время ожидания.

Автоматический пересмотр отказов, повторная отправка и исправление опубликованных сообщений из аудита не запускаются. Запуск ИИ запрещён при остановке агента владельцем.

## Навигация и проверки

- `AGENT_LOGIC.md` — технический контракт и восстановление после сбоев.
- `EDITORIAL_RULES.md` — редакционные правила; рабочие версии — `newsroom/edition/policy.json` и `references.json`.
- `MODULES.md` — карта действующих модулей.
- `INTEGRATIONS.md` — подключение источников и темника.
- `docs/updates/` — описания отдельных изменений; `CHANGELOG.md` — история, включая прежнюю редакцию.
- `docs/archive/legacy-tests/` — исторические проверки удалённых модулей, вне обычного запуска.
- `experiments/` — ручные исследовательские сценарии, не часть службы и не обычные тесты. Их результаты в `exports/` не входят в Git.

Для проверки используйте отдельное окружение с зависимостями проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m unittest discover -s tests
```

Сравнение выпуска с Git выполняется без изменения сервера:

```sh
git fetch origin main
python3 ops/check_release.py --release <каталог-выпуска> --ref origin/main
```

Отчёт показывает различия исходников, отсутствующие и дополнительные файлы. Название каталога выпуска само по себе не доказывает соответствие коммиту.
