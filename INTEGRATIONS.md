# Оценка Web Search, X и YouTube

Обновлено: 29 сентября 2026 года. Решение редакции: **Web Search нужен, X нужен, YouTube избыточен**. Решение зафиксировано. Web Search подключён к штатному циклу с общим интервалом 15 минут; адаптер X API v2 реализован, но его живой сбор ждёт bearer token.

## Web Search — подключить

В приложении уже используется OpenAI Responses API. Его встроенный инструмент `web_search` можно вызвать в том же API, не вводя второго поставщика поиска. Однако он возвращает результаты поиска с цитируемыми URL в контексте модельного ответа, а не гарантированную исчерпывающую ленту структурированных публикаций. Поэтому применять его как дополнительный канал обнаружения: находить события и первичные страницы, а затем передавать их в обычный конвейер чтения, дедупликации и редакционной проверки. Один лишь ответ поиска не считается подтверждением и не может служить основанием автопубликации.

Расходы в официальном прайс-листе OpenAI указаны отдельно за вызовы поиска и входные токены; итог зависит от модели и объёма возвращённого текста. Общий лимит — один запрос раз в 15 минут; очередь чередует широкие темы, восстановление первоисточника и наблюдение за сюжетами. Момент последнего запроса хранится в базе и переживает перезапуск.

## X — подключить через официальный API

Использовать X API v2 Recent Search (`/2/tweets/search/recent`): актуальная документация описывает поиск постов за последние 7 дней, до 100 постов на запрос и пагинацию. Это подходит для периодического обнаружения свежих заявлений компаний, ведомств и участников рынка. Для запросов потребуется одобренный аккаунт разработчика, приложение и ключи/токены. X API v2 тарифицируется по использованию/кредитам; точную цену перед запуском следует проверить в Developer Console и ограничить месячный бюджет.

Сохранять ID, URL, автора и время поста, дедуплицировать по ID. Пост в X сам по себе — сигнал, а не независимое подтверждение: искать официальный документ, заявление организации или другой исходный материал и читать его штатным путём. Ошибка авторизации, квота и rate limit должны отражаться в здоровье источников без утечки токенов. Не использовать неофициальный скрейпинг.

## YouTube — исключить

По решению пользователя интеграция избыточна для текущего продукта. Отдельных задач на API, транскрибацию или извлечение роликов не заводить.

## Текущий результат

Web Search активен в `config.toml`: один общий запрос не чаще чем раз в 15 минут. Очередь по очереди выдаёт слот широким темам, поиску первоисточника и наблюдению за сюжетами; отложенный вызов не тратит попытку материала. Цитируемые URL передаются в чтение страниц издателей; если страницу прочитать не удалось, материал не попадёт дальше как подтверждённая новость. В кабинете видны группы Web Search и X.

X Recent Search использует официальный endpoint и уже интегрирован в сборщик, базу, редакционный проход и кабинет. Настройка источника добавлена неактивной, чтобы до появления токена не засорять журнал ошибками авторизации. Для включения достаточно задать `X_BEARER_TOKEN` в окружении LaunchAgent или положить bearer token в защищённый локальный файл `data/x_bearer_token`, затем активировать источник в `config.toml`. Посты X сохраняются как прямая атрибуция автора; дата, ID/URL и текст приходят из API. После включения нужно проверить квоты и стоимость в Developer Console.
