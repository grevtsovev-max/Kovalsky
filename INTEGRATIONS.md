# Внешние интеграции

## Общий справочник Google Таблиц

Аутентифицированный кабинет принимает настройки через `POST /api/source-registry`:
ссылку `url` и список `tabs` с проверенными названиями `name` и числовыми `gid`.
Настройки и последняя корректная копия хранятся в рабочей базе, а не в Git или
файле конфигурации. `GET /api/source-registry` показывает состояние и допуск строк.

Таблица читается без изменения содержимого через HTTPS CSV-экспорт. Для этого
серверу нужен доступ на чтение без Google-сессии; подключение Google Drive в чате
само по себе не предоставляет серверу OAuth-доступ. Права таблицы автоматически
не меняются. Поддерживаются заголовки «Название»/«Имя», «Ссылка» и необязательное
«Что отслеживать». Пробелы в заголовках допустимы.

Синхронизация запускается в штатном цикле сбора не чаще раза в три минуты.
Новая копия сохраняется только после успешного чтения всех указанных вкладок;
при ошибке используется прежняя копия и показывается ошибка. Таблица определяет полный состав
мониторинга по уникальным URL. Прежние настройки используются только для
адаптера чтения, приоритета, доверия и роли совпадающего адреса; адреса вне
таблицы не собираются. Удаление строки или смена URL прекращают опрос прежнего
адреса после синхронизации, история материалов сохраняется. При пустой корректной
таблице сбор по справочнику останавливается; при ошибке чтения прежняя копия
таблицы действует без возврата к списку из конфигурации.

Публичные Telegram-каналы, RSS и Google News подключаются к обычному сбору.
Обычные сайты без настроенного адаптера сохраняются в справочнике с пометкой
о необходимости RSS. Необязательная колонка «Мониторинг» принимает галочки TRUE/FALSE; пустая
ячейка при наличии этой колонки означает выключение. Без колонки старый
двухколоночный формат остаётся совместимым и включает все записи. FALSE отключает прямую ленту и поиск
упоминаний этой строки. Если один адрес указан в нескольких строках, он читается,
пока включена хотя бы одна из них. Кабинет направляет правки источников в таблицу
и блокирует добавление в прежний локальный список. Нормативный мониторинг
использует адаптеры только для включённых официальных доменов из таблицы;
удалённые источники исключаются также из повторного нормативного обхода.

Каждая включённая строка, включая СМИ, регулятора или источник с лентой, также
задаёт объект наблюдения. Имена без ссылок участвуют в поиске упоминаний.
Google News ищет точные имена с тематическими словами за последние два дня:
до восьми имён в группе и четырёх групп за цикл, с сохраняемой круговой очередью.
Полный обход зависит от числа групп и длительности цикла. Поиск не заменяет
чтение публикации; тематические, географические и редакционные фильтры сохраняются. Раздел не подтверждает
официальность, авторство или доверие. Ссылки проходят проверку публичного HTTPS-адреса;
все найденные материалы проходят обычные редакционные проверки.

## Поиск в интернете

Web Search через OpenAI Responses API используется как дополнительный способ находить материалы и документы. Результат поиска сам по себе не является основанием для публикации: найденная страница должна быть прочитана, атрибутирована и пройти общий редакционный конвейер.

## X

Адаптер X API v2 поддерживает Recent Search. Источник включается только после настройки `X_BEARER_TOKEN` и проверки квоты. Сообщение в X служит сигналом и проходит те же проверки, что и другие материалы; неофициальный скрейпинг не используется.

## YouTube

Отдельная интеграция с YouTube не входит в текущий продукт.

## Учётные данные

Не добавляй ключи и токены в Git. На рабочем сервере они задаются через защищённую конфигурацию или файл с ограниченными правами доступа.

## Единый темник в Google Таблицах

Подключение: аутентифицированный `POST /api/topic-registry` с `url` и четырьмя
вкладками `{name,gid}`. Заголовки:

| Вкладка | A | B | C |
| --- | --- | --- | --- |
| Темы | Тема | Что отслеживать | Мониторинг |
| Ключевые слова (старый формат) | Тема | Слово или фраза | Мониторинг |
| Исключения | Неинтересный материал | Когда исключать | Применять |
| География | Регион | Когда включать | Учитывать |

Основной формат вкладки «Ключевые слова»: **Ключевик | Мониторинг | Роль | Уточнение**.
Тема не требуется и не управляет включением этих ключей. Достаточно вписать ключевик:
пустой мониторинг означает включение, пустая роль — «Профильный». FALSE явно выключает
строку. Роли «Контекстный» и «Требует уточнения» сохраняют прежние условия допуска;
для включённого слова с уточнением обязателен список фраз через `|`.
Старый формат продолжает читаться с прежними значениями по умолчанию и зависимостью
от тем. При переносе сохраняются роли и уточнения, а отключение темы преобразуется
в FALSE у связанных ключей. Добавление из обучения в новый формат не требует темы.
Серверный Apps Script должен быть обновлён из `newsroom/integrations/kovalsky_topics.gs`
для чтения и записи четырёх колонок.

`GET /api/topic-registry` показывает версию, дату, включённые строки, ошибку чтения
и доступность записи. `GET /api/topic-registry/learned` возвращает накопленные
темы с ключами для однократной сверки. Настройки и копия находятся в рабочей
`app_state`; содержимое таблицы не помещается в исходники. Чтение использует
публичный CSV-экспорт, максимум 10000 строк на вкладку. Все вкладки должны быть
корректны; неизвестное название темы в ключах не применяется частично.

Темник читается в основном цикле, а сохранённая версия передаётся независимым
процессам. В сохранённых заданиях старый буквальный фильтр игнорируется. Версия
темника входит в ключи ИИ-кешей. Историческая `monitoring_topics` сохраняется для
аудита, но перестаёт задавать темы поиска и фильтра. Семантическое решение не
гарантирует полный охват интернета; морфология — подсказка, не перечень всех синонимов.

### Запись изменений из обучения

Все новые комментарии, тематические примеры и оценки становятся устойчивыми
заданиями `topic_learning:*`. Тематический план ограничен десятью изменениями и
должен опираться на цитату из сигнала. Обычный отрицательный отзыв не запрещает
целую тему. Авторитетом становится только перечитанная таблица, а не предложение.

Для сервера подготовлен OAuth 2.0 writer. В закрытом окружении сервиса задаются
`GOOGLE_SHEETS_CLIENT_ID`, `GOOGLE_SHEETS_CLIENT_SECRET` и
`GOOGLE_SHEETS_REFRESH_TOKEN`, выданный с scope
`https://www.googleapis.com/auth/spreadsheets` пользователю с правом редактировать
именно этот файл. Google Sheets API должен быть включён в Google Cloud проекте.
Разовый `GOOGLE_SHEETS_ACCESS_TOKEN` подходит только для диагностики: он истекает.
OAuth-значения не принимаются через кабинет, не сохраняются в базе или Git и не выводятся
в диагностике. OAuth-клиент и refresh token оформляются в Google Cloud/Google,
после чего передаются в приватное окружение сервера и процессы перезапускаются.
Учётные данные Google-коннектора Codex не извлекаются и не копируются на сервер.

Без доступа новые планы остаются `BLOCKED` с причиной
`GOOGLE_SHEETS_WRITE_ACCESS_MISSING`; мониторинг продолжает читать таблицу. После
выдачи доступа writer подхватит очередь. При неизвестном результате повтор сначала
читает актуальные строки и проверяет дубли. Три неудачи дают `NEEDS_REVIEW`, не
бесконечную перезапись. Условная замена описания и вставка строк сохраняют соседние
правки. Отключение строки разрешено только по явному требованию владельца.

### Отдельный служебный аккаунт Google

Предпочтительный серверный вариант — выделенный service account без делегирования
пользовательского аккаунта. В его Google Cloud проекте включается Google Sheets API;
email получает роль редактора конкретного темника. Роли администратора Google Cloud
для работы с самой таблицей не требуются.

В кабинете → «Источники» → «Подключить служебный аккаунт Google для обучения»
владелец выбирает JSON-ключ, скачанный из Google Cloud. Аутентифицированный
`POST /api/topic-registry/credentials` проверяет тип ключа, служебный email и фиксированный
Google OAuth endpoint, получает токен со scope `spreadsheets` и проверяет право
редактирования условной заменой заголовка B1 на то же значение. Только успешная проверка
активирует аккаунт. Проверка сохраняет значения и оформление ячеек.

Ключ атомарно сохраняется с правами 0600 рядом с рабочей базой, вне исходников;
SQLite содержит только путь, email и дату подтверждённой проверки. Ключ не возвращается
API и не журналируется. Чтение отклоняет символические ссылки и доступные другим
пользователям файлы. Подпись RS256 выполняет системный OpenSSL: приватный ключ
передаётся через анонимный канал, не через аргументы процесса или временный файл.
Google access token используется только в памяти. Перезапуск сервиса для подключения
не нужен: процессы читают актуальные настройки перед работой с очередью.

Создание служебного аккаунта и ключа требует авторизованного входа владельца проекта
в Google Cloud; подключение Google Drive в Codex не даёт полномочий Google Cloud IAM.
До получения ключа и успешной проверки права редактора автоматическая запись не активна.

### Простое подключение через Apps Script

Встроенный в таблицу скрипт `newsroom/integrations/kovalsky_topics.gs` можно
скопировать из кабинета → «Источники» → «Обучение через таблицу».
Владелец открывает «Расширения → Apps Script», вставляет код, добавляет в разделе
«Сервисы» Google Sheets API, сохраняет и запускает `setupKovalsky`.
Google запрашивает разрешения; скрипт сохраняет ID именно текущей таблицы и
случайный код доступа в Script Properties. Повторный запуск сохраняет код.
Код появляется в окне самой таблицы, а не в журнале выполнения.

Затем владелец выбирает «Развернуть → Новое развертывание → Веб-приложение»,
выполнение от своего имени, доступ «Все». Адрес `/exec` и код доступа вводятся
в закрытой форме кабинета. Этот адрес принимает запросы извне, но без кода
доступа не читает и не меняет таблицу. Для автоматически созданного проекта Apps
Script добавление сервиса включает API; отдельный проект Google Cloud и JSON-ключ
служебного аккаунта не нужны. Создание и развертывание выполняет владелец в Google.

`POST /api/topic-registry/apps-script` проверяет реальную запись заменой заголовка
B1 на то же значение, затем активирует bridge. Адрес и код хранятся с правами 0600
рядом с рабочей базой; API отчёта не возвращает их. Допустим только HTTPS-адрес
`script.google.com/macros/s/.../exec`, перенаправление ответа — только на
`script.googleusercontent.com`. Ошибки и ответы Google не попадают в диагностику.

Прокси проверяет привязку ID таблицы, секрет, перечень вкладок, координаты,
типы ячеек и разрешённые операции. Удаление вкладок, строк, форматирование,
формулы и запросы к другим таблицам недоступны. Обновления выполняются штатным
Sheets batchUpdate атомарно; условные замены и вставки строк сохраняют прежнюю
защиту ручных правок. Google OAuth-токен не передаётся на сервер.

Чтение темника продолжает использовать прежний CSV-кеш. Очередь обучения работает
с тем же темником и возобновляется после успешного подключения без перезапуска.
При смене таблицы доступ требуется проверить заново. При выборе служебного аккаунта
он заменяет Apps Script как способ записи.

Если владелец не имеет доступа к закрытому кабинету сервера, можно выполнить
`exportKovalskyConnection` в редакторе уже развернутого скрипта. Функция создаёт
отдельную новую таблицу с URL, секретом и ID темника, без выдачи доступа по ссылке.
Секрет нельзя записывать во вкладку публичного темника. Для импорта через подключённый
Google Drive сначала проверяются права временного файла: только владелец, без доступа
`anyone`, `domain` и дополнительных редакторов/читателей. Данные передаются в штатный
аутентифицированный вход кабинета без вывода секрета в чат, журналы или аргументы процесса.
Реальная проверка записи остаётся обязательной. После подтверждённого подключения
временный файл переносится в корзину; секрет хранится только в приватном файле сервера
и Script Properties владельца. Ссылку на временный файл можно передать в чат; его
общий доступ менять не требуется. Переразвертывание веб-приложения не требуется:
дополнительная функция выполняется в редакторе, а рабочий endpoint не меняется.


## Состояние редактора

Прежние редакторские вкладки, их синхронизация и обучение удалены по команде владельца. Подключения источников и темника сохраняются.

## Новая редакция

В текущей таблице вкладки «Редполитика» и «Референсы» содержат сверенную копию версии 2026-10-09-v4. Рабочий модуль читает файлы этой версии из выпуска; правки таблицы сами по себе ещё не изменяют код. Старые редакторские вкладки и архив обучения не применяются.
