# Работа над Kovalsky

## Проект и данные

- Работай в корне текущего репозитория Kovalsky. Не используй архивы и старые снимки как рабочую копию.
- Не добавляй в Git личные конфиги, базы, журналы, ключи, токены, имена пользователей и локальные пути.
- Перед изменением системной логики прочитай `AGENT_LOGIC.md`.

## Новая редакция

- По согласованию с владельцем реализуется новая редакция с нуля. Перед изменением текста или правил читай `EDITORIAL_RULES.md`.
- Рабочие правила и референсы — `newsroom/edition/policy.json` и `references.json`; старая редактура не используется.
- Обычный поток автоматически готовит, проверяет и публикует посты без ручного одобрения. Проверки не блокируют выпуск: после одной доработки — текст с замечаниями либо резервный фрагмент исходника. Каждый выпуск записывается в журнал доставки; опубликованные сообщения не удаляй.
- Поиск редактора — только сохранённые материалы; одна доработка. При ошибке подготовки и после перезапуска выпуск продолжается по исходнику; причины и версии сохраняются.
- Неизвестный результат Telegram не повторяй вслепую. Остановка агента владельцем имеет приоритет над включением редакции.

## Изменения и выпуск

- Изменения ветки `main` в `newsroom/` и `KANBAN.json` автоматически выкладываются на сервер. Документация сама по себе приложение не перезапускает.
- Не помещай секреты и рабочие базы в выпуск. Производственные настройки и данные хранятся отдельно от исходников.

## Отключение агента

- По команде «отключить агента» сначала выполни `newsroom --config <рабочая-конфигурация> agent disable`, затем останови сборщик и редакторского бота. Сохраняй запрет вне выпуска; остановки процесса недостаточно.
- Включать через `agent enable` можно только по явной команде владельца включить агента. Обновления, проверки и исправления не дают такого разрешения. Кабинет оставляй доступным.
