# История изменений Kovalsky

## 2026-10-02 — Защита от публикации материалов из задержанной очереди

- Окно свежести автоматической ленты снижено с 48 до 24 часов.
- Материал, обработанный позже 24 часов после публикации, автоматически отклоняется до создания поста, даже если система обнаружила его раньше.
- Дата подтверждённого позднего развития по-прежнему может обосновать новую публикацию, если само изменение произошло в пределах окна свежести.

## 2026-10-02 — Прямая публикация по команде владельца

- Для материалов, разобранных в Codex-чате, добавлена команда CLI `admin-publish`: текст уходит в канал без редакционных проверок только после явного сообщения владельца «публикуй»/«опубликуй».
- Запросы Codex-чата хранятся отдельно в `codex_publication_requests`; устойчивый ключ и общий журнал `deliver` предотвращают дубли и сохраняют подтверждение Telegram.
- В редакторском боте добавлена команда `/publish` для владельца из личного чата; она отправляет переданный текст без редакционных проверок отдельным потоком.
- Запросы сохраняются в `admin_publication_requests`, а доставка идёт через общий журнал `deliver` со стабильным ключом и фактическим подтверждением Telegram.
- Неопределённый результат блокирует повторную отправку; бот не сообщает об успехе без сохранённого `message_id`.

## 2026-10-02 — Проверка даты в английском формате

- Автоматическая проверка даты события распознаёт полные английские названия месяцев, например `October 01, 2026`, наряду с цифровыми и русскими форматами.
- Если прежний цикл закрыл материал только из-за этой ошибки распознавания, новый цикл начинается лишь после доказуемого прохождения сохранённой цитаты через исправленную проверку; старый цикл остаётся в истории.

## 2026-10-02 — Повтор после восстановления AI-баланса

- Если пользователь подтвердил восстановление баланса, а сохранённый терминальный результат подтверждает три ошибки `credit_balance_exhausted` до редакционного отбора, исходный материал можно вернуть в полный автоматический конвейер.
- Предыдущий цикл сохраняется в `app_state`; он не удаляется, а новая попытка снова ограничена тремя повторами и проходит все прежние проверки.

## 2026-10-02 — Восстановление даты при разовой передаче

- Извлекатель читает дату из семантического тега `time datetime`, в том числе на страницах FinCEN.
- Материал, остановленный только из-за отсутствующей даты, повторно проходит штатную обработку после извлечения явной даты; другие закрытые версии и лимиты AI-повторов не сбрасываются.
- Для краткой официальной страницы с прочитанным приложенным документом тематический фильтр использует текст самого официального документа; заголовок берётся из H1 страницы, когда метаданные содержат только название бренда.

## 2026-10-02 — Разовая передача статьи по ссылке

- В кабинете редакции добавлена форма передачи публичной HTTPS-ссылки на отдельную статью или исследование.
- Текст страницы извлекается и проходит общий автоматический конвейер; отправка в Telegram ограничена только постами, созданными из этого материала, и остаётся за штатным допуском.
- Для раннего тематического фильтра без RSS-анонса используется заголовок и начало прочитанной статьи; повторная передача ссылки повторяет штатную обработку в той же записи.
- Добавлены проверка публичности URL и редиректов, локальная блокировка параллельного цикла и отображение результата обработки в кабинете.

## 2026-10-01 — Проверка возраста самого события

- Разбор отдельно устанавливает дату последнего существенного изменения и требует точную цитату из прочитанного первичного источника; дата новой статьи или её обнаружения не подменяет дату события.
- Событие, подтверждённое только старой датой за пределами окна свежести, отклоняется до создания сюжета и черновика. Неподтверждённая дата уходит на ограниченную автоматическую перепроверку.
- Версия редакторского фильтра повышена до 23.

## 2026-09-30 — Постоянный запуск вебкабинета

- Добавлен отдельный macOS LaunchAgent для кабинета: запуск при входе в пользователя и автоматический перезапуск после завершения процесса с ограничением частоты повторного старта.
- LaunchAgent установлен и загружен в текущую пользовательскую сессию; кабинет отвечает на `http://127.0.0.1:8765`.
- README уточняет ограничение локального запуска: кабинет недоступен во время сна или выключения Mac.

## 2026-09-29 — Приоритет свежих новостей

- Ограничены повторы отложенных материалов: не более двух за цикл. Замеры показывали, что повторы занимали значительную часть цикла и задерживали чтение свежих лент; ожидание повторной попытки по-прежнему не расходует попытку.
- Отложенные повторы перемещены за сбор свежих лент и адресный поиск продолжений, чтобы очередные попытки не задерживали получение новых материалов.
- Тайм-аут источника больше не повторяется немедленно с тем же лимитом ожидания: следующий штатный цикл сам повторит чтение, что сокращает задержку при общей потере сети.
- Синхронизированы лимит обработки и оценка очереди в кабинете; значение 0 теперь действительно отключает обработку повторов в цикле.
- Сводка здоровья отдельно показывает, сколько пропущенных при подключении материалов ещё остаются в окне свежести сейчас, вместо того чтобы называть весь старый архив требующим редакционного разбора.

## 2026-09-29 — Исправление дайджеста

- Добавлены формы «допускает» и «подала» в сборку дайджеста и общий редакционный допуск кликабельного действия. Ранее заголовки с этими словами останавливали выпуск.

## 2026-09-29 — Прямая связь новости с публикацией

- Каждый новый черновик хранит идентификатор новости, которая его создала; прежние посты связываются автоматически только по неизменяемой записи памяти.
- В карточке новости раскрываются точный текст поста, способ связи с исходным материалом и сохранённые этапы отправки.
- Показываются статус попытки, безопасная причина ошибки, Telegram message_id и ссылка на сообщение. Старые сопоставления по URL/времени обозначаются как предположительные.
- Финальный допуск распознаёт ещё одну форму служебной заметки: отсутствие прежних заявлений в переданном архиве.
- Для точной связанной публикации карточка показывает итог поста даже если состояние новости позже изменил разбор сюжета.

## 2026-09-29 — Объяснимая история новости

- В карточке обработки показывается, запускался ли полный ИИ-разбор; ранний фильтр больше не выглядит как потерянный ответ ИИ.
- Для новых решений сохраняется цепочка этапов и конкретная причина отсева, ожидания или передачи на автоматический допуск.
- В карточке добавлена сворачиваемая история последних восьми проходов. Старые записи без точной причины честно обозначаются как неполные.
- Повторный пакет увеличен с четырёх до восьми материалов за цикл в рамках прежних общих бюджетов ИИ. Время допуска больше не называется временем фактического запуска: карточка поясняет ожидание места в очереди.
- Для ожидающих материалов показываются место в очереди, размер пакета и примерное число циклов до обработки; расчёт учитывает только допущенные к повтору материалы и активные источники.

## 2026-09-29 — Очередь повторного анализа

- Отпечаток исходной ленты отделён от текста прочитанной статьи: очередной опрос источника больше не стирает анализ и счётчик повторов только потому, что в записи хранится полный текст страницы.
- Отложенные из-за лимита цикла проверки больше не считаются неудачной попыткой и явно показывают причину и ближайший цикл.
- Повторные материалы ограничены четырьмя за цикл, чтобы оставить бюджет для новых новостей.
- В карточке очереди показываются возраст материала, время последней обработки, счётчик реальных повторов и момент, с которого повтор готов к запуску.
- Снимки версий используются для однократного закрытия тех неизменённых материалов, которые уже прошли первоначальный и три повторных разбора до исправления сбрасываемого счётчика.

## 2026-09-29 — Исправления по самоаудиту

- Повторная версия материала по тому же каноническому URL сохраняется в `item_revisions`; изменённый материал снова проходит обычный отбор, а прежний разбор остаётся в снимке версии.
- Лимит Web Search стал общим: один запрос за настроенный интервал, сейчас 15 минут. Очередь чередует широкие темы, поиск первоисточника и наблюдение за сюжетами; отложенный вызов не считается неудачной попыткой.
- Если поисковый API и резервный RSS-поиск оба завершаются ошибкой, журнал сохраняет оба безопасных кода, чтобы отличать сбой API от отказа резервного источника.
- Для точного прочитанного сообщения в соцсети выдержка из заголовка сообщения может восстановить отсутствующую цитату, если сохранена атрибуция и факты отмечены как CLAIM/REPORT/OPINION. Свежие прежние отказы, удовлетворяющие тем же строгим условиям, переоцениваются один раз по новой версии фильтра.
- Фильтр готового текста распознаёт служебные фразы о неудачном поиске и несопоставленных материалах.
- Кабинет и нормативный снимок открывают базы только для чтения. Ошибки чтения отдельной статьи не переводят успешно полученную ленту в состояние сбоя.
- В замерах цикла отдельно выделен story watch. Постоянный запуск поддерживает целевой интервал между стартами, а метаданные проекта допускают фактически используемый Python 3.9.
- AI-фильтр обновлён до версии 22. Исходные базы, конфигурация, ключи, логи и архивы исключены из истории исходников.

Проверка: `python3 -m unittest discover -s tests -q` — 241 тест прошёл.


## 2026-09-29 — Резерв очереди повторного анализа

- Два места цикла резервируются для отложенных материалов после обработки свежих лент и наблюдения за сюжетами; интенсивный поток новых новостей больше не может постоянно вытеснять повторы.
- При сетевом тайм-ауте источник больше не запрашивается повторно сразу в том же цикле.

## 2026-09-30 — Обратная связь по ссылке из Telegram

- Владелец может прислать редакторскому боту ссылку на пост канала и комментарий; бот проверяет канал и опубликованный message_id, сохраняет отзыв с привязкой к посту и отвечает о результате.
- Повторная доставка одного Telegram update не создаёт второй отзыв.
- Прямой отзыв владельца отмечен в инструкциях модели как сильное редакторское предпочтение с обязательной проверкой фактов по источникам.

## 2026-09-30 — Исправление поста по обратной связи

- После отзыва по ссылке бот ставит публикацию в фоновую очередь, сопоставляет комментарий с сохранённой прочитанной статьёй и предлагает только точечные замены.
- Фактологические замены допускаются при точной выдержке из источника; готовый пост проходит редакционную и структурную проверки, а строка источника сохраняется без изменений.
- Подтверждённая правка редактирует то же сообщение Telegram с прежним `message_id`. Журнал фиксирует намерение и фактический ответ; неизвестный результат не отправляется повторно вслепую.
- Владелец получает результат проверки: исправление, отсутствие подтверждённой ошибки или причину отказа.
