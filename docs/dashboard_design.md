# Дизайн кабинета Kovalsky

Единственная актуальная версия кабинета: `materials-path-v2` с исправлением
`stage-counts-2`, зафиксированная владельцем 8 октября 2026 года.
Зелёное оформление само по себе не подтверждает актуальность: обязательны
названия и правила счётчиков ниже. Ранние версии с прежними названиями
и расчётом этапов не должны возвращаться при выпуске.

Рабочий экран материалов называется `Материалы` и открывается по `/?view=pipeline`.
Он показывает один зелёный кабинет с левым меню и верхней полосой `Путь материалов`.
Полоса этапов использует `path-strip` и семь шагов нового конвейера:

1. Собрано
2. Отобрано по теме
3. Текст получен
4. Разобрано ИИ
5. Пост сохранён
6. Текст проверен
7. Опубликовано

Чтение учитывается только после сохранённого допуска текущей версии материала.
Полученный при сборе текст Telegram сам по себе не означает прохождение этого шага.
Проверка опубликованного поста сверяется с сохранённым текстом перед отправкой;
изменение отображения ссылки в Telegram не отменяет выполненную проверку.

Старый экран `Обработка материалов` из ветки `codex/cabinet-redesign` больше не является
источником правды. Его элементы `Где сейчас каждый материал` и `pipeline-stages` нельзя
возвращать в активный кабинет: они описывают прежнюю модель этапов и конфликтуют с
пересобранным конвейером.

История решений:

- `a925cfc` (`codex/cabinet-redesign`) дал зелёную оболочку кабинета и отдельный экран
  обработки материалов.
- Локальная сессия Codex `2026-10-07T19-29-21` зафиксировала промежуточную идею:
  разделить экран на «Что прошли материалы» и «Где они сейчас», чтобы накопительные
  счётчики не путались с текущей очередью. Эта версия объясняет происхождение
  старых элементов `Обработка материалов` и `pipeline-stages`, но не является
  текущим интерфейсом после пересборки этапов.
- `427b386`, `4349c80`, `7d3e732` пересобрали кабинет вокруг пути материала и новых
  этапов конвейера.
- `e54eed3` и последующие локальные исправления ускорили чтение архива и API кабинета.

Правило работы: любые изменения дизайна кабинета сначала сверяются с этим документом и
тестом `tests/test_dashboard_design.py`. Если нужно менять навигацию, названия этапов
или структуру экрана материалов, сначала обновляется этот документ, затем код кабинета
и тест.


## Сохранение оболочки при замене редакции

Новая редакция не разрешает заменять зелёный кабинет технической страницей.
Оболочка в `newsroom/dashboard_shell.py` сохраняет зелёную палитру, левое меню
и экран материалов независимо от реализации редактора. Проверка
`tests.test_dashboard_shell` обязательна перед автоматическим выпуском.
Семь счётчиков выше описывают прежний API конвейера; новая редакция не должна
показывать их без соответствующих сохранённых результатов. Их отсутствие
не даёт разрешения менять утверждённое оформление.


## Восстановление полного кабинета 9 октября 2026 года

`newsroom/cabinet_page.py` сохраняет утверждённый экран из `1e9845b`: путь,
вкладки состояний, период, поиск, карточки и раскрываемую историю.
`newsroom/cabinet_pipeline.py` — только адаптер чтения; он объединяет исторические
результаты с материалами, документами и проверками `edition_*`. Старый редактор
не запускается и не восстанавливается. Для новой редакции каждый исходный материал
считается один раз на этапе, даже если дал несколько документов; публикация
подтверждается записью поста и внешним идентификатором. Проверка текста учитывается
по хешу текущего сохранённого текста. Вкладка «Редакция» показывает задания,
исходники, версии и проверки действующего модуля. Выпуск проверяет полную страницу
и адаптер, а не только наличие зелёных цветов.


## Последовательные счётчики 10 октября 2026 года

Основная полоса — подтверждённая последовательность для одной группы материалов:
каждый следующий шаг требует доказательств всех предыдущих, включая текущий допуск.
Наличие позднего результата не подставляет отсутствующее доказательство раннего шага.
Независимые сохранённые результаты доступны отдельно в раскрываемой сводке
`evidence_totals`; архивные карточки и публикации не удаляются. Переход по этапу
использует ту же последовательную выборку, что и число на карточке.
