# Независимый модуль вакансий

`newsroom/jobs/` читает сохранённые сборщиком записи `items` и `sources`. Он не импортирует редакцию, её планировщик, проверки или доставку. Изменения исходников создают новую версию задания. Первичная очередь включает кандидатов за последние семь дней; после этого собственный курсор отслеживает поступления независимо от новостных фильтров.

Собственные таблицы: `recruitment_queue`, `recruitment_cards`, `recruitment_attempts`, `recruitment_cursor`. Общие новостные записи не изменяются. Один исходник может содержать несколько вакансий. Резюме и прочие объявления сохраняются как классифицированные задания без карточки вакансии.

Собственный запрос ИИ извлекает должность, компанию, контакт нанимателя, зарплату, локацию и формат работы. Каждое значение подтверждается дословной цитатой исходника. Название канала, домыслы, хештеги, рекламные фразы и призывы к отклику не допускаются в полях. Неуказанные сведения остаются пустыми. Исходник, ответ и квитанция сохраняются; неподтверждённый ответ не становится карточкой. Ошибка переводит только одно задание в ожидание. Повтор выполняется только при следующем явном запросе владельца.

Модель задаётся `ai.vacancy_model`, при отсутствии используется `ai.model`. Транспорт OpenAI и общий журнал лимитов используются повторно; редакционные промпты и очередь не используются. Интернет-поиск и Telegram-доставка отсутствуют. Постоянный запрет владельца проверяется до вызова и после ответа; модуль не включает агент.

Кабинет читает только результаты нового модуля через `newsroom/vacancy_view.py`. Старые редакционные таблицы сохраняются, но не являются источником карточек. В редакционном запросе остаётся классификация типа содержимого для отделения объявления от новости; извлечение полей отключено (`vacancies` — пустой массив).

Ручной запуск: кнопка «Разобрать вакансии» отправляет защищённый POST `/api/vacancies/parse`. Кабинет запускает отдельный конечный процесс `python -m newsroom.jobs.worker --config CONFIG_FILE`; для одного объявления доступен `--once`. Постоянного сервиса и планировщика нет. Процесс фиксирует набор накопившихся заданий, обрабатывает каждое один раз и завершается. Поздние поступления ждут следующего запроса. Чтение и обновление кабинета не вызывает ИИ. Запуск защищён токеном кабинета, проверкой остановки владельца и отдельной блокировкой процесса.

Проверки: `python -m unittest tests.test_jobs tests.test_vacancy_fields tests.test_dashboard_shell`, затем `PYTHONPATH=tests:. python -m unittest test_edition_vacancies`.
